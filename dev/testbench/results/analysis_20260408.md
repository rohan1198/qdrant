## Analysis

### Positive Findings

**1. Busemann depth separation works (sep_ratio ~6.2-6.4)**

The Busemann depth cleanly separates the three tiers across all curvatures:
- Root (domains): avg depth ~0.37 (c=0.5) to ~10.0 (c=5.0)
- Mid (areas): avg depth ~0.53 (c=0.5) to ~10.2 (c=5.0)
- Leaf (papers): avg depth ~1.00 (c=0.5) to ~10.7 (c=5.0)

Ordering is consistent: root < mid < leaf. Separation ratio >6.0 is strong — well
above our 1.0 success threshold. This validates that even with the projection issue
(see below), the hierarchy IS being captured.

**2. Poincaré search works end-to-end**

All collections accept queries, return results, and produce meaningful scores.
The fork's `Distance::Poincare` integration with HNSW, scorer dispatch, and the
REST API all work correctly. No crashes or errors.

**3. Latency is acceptable**

Poincaré p95 ranges from 2.7ms (c=0.5) to 4.1ms (c=5.0), well under our 50ms
target. Higher curvature = slower (larger distance values mean more numerical work
in acosh). Cosine is fastest at 2.4ms (simpler computation).

**4. Curvature c=5.0 shows best retrieval numbers among Poincaré**

c=5.0 has the highest area recall (0.196), domain recall (0.578), and hierarchical
precision (0.387) among Poincaré collections — nearly matching cosine baseline.

### Known Issue: Uniform Radius Projection

**All vectors land at the same ball radius within each curvature.** The embedding
pipeline applies L2 normalization + ball_scaling (0.9) + exp_map, which maps every
vector to approximately the same norm:
- c=0.5: norm = 0.9500 (all points)
- c=1.0: norm = 0.9500
- c=2.0: norm = 0.7071 (= 1/√2, the ball boundary)
- c=5.0: norm = 0.4472 (= 1/√5, the ball boundary)

This means root/mid/leaf documents are all at the same depth in the Poincaré ball.
The Busemann separation we observe comes from DIRECTION differences (different areas
of the ball surface), not DEPTH differences (distance from origin).

**Impact:** Retrieval quality is roughly comparable to cosine because all points are
on a shell — Poincaré distance on a constant-radius shell degenerates toward angular
distance. The hierarchy IS encoded (Busemann picks up directional structure), but
the full power of hyperbolic depth-encoding is not being leveraged.

### Root Cause & Fix

The projection pipeline needs to assign different radii based on tier:
- Root/domain documents: project closer to origin (low norm, ~0.1-0.3)
- Mid/area documents: project to intermediate radius (~0.4-0.6)
- Leaf/paper documents: project near boundary (~0.8-0.95)

**Fix approach: Tier-aware scaling**

Instead of uniform `ball_scaling = 0.9` for all documents, use tier-dependent scaling:

```python
TIER_SCALING = {
    "root": 0.15,   # near origin — abstract concepts
    "mid":  0.50,   # intermediate — topic clusters
    "leaf": 0.90,   # near boundary — concrete documents
}

def project_with_tier(vector, tier, c=1.0):
    scaling = TIER_SCALING[tier]
    scaled = vector * scaling  # L2-normalized vector * tier scaling
    mapped = exp_map_at_origin(scaled, c)
    return project_to_ball(mapped, c)
```

This gives each tier a distinct radial band in the Poincaré ball, enabling Busemann
depth to reflect both direction AND depth. Expected improvement: significantly
better Busemann separation, and Poincaré recall should outperform cosine because
within-tier search (all leaves) uses the full hyperbolic metric while cross-tier
queries naturally respect the radial hierarchy.

**Alternative: Learned projection**

Instead of hardcoded tier scaling, learn a radius mapping from the data:
1. Compute Frechet/Einstein midpoint per area → these become the "mid" positions
2. Compute midpoint per domain → these become "root" positions
3. Individual papers naturally scatter near the boundary
This matches Pythia's actual pipeline more closely (centroids for stories/narratives).

### Why Retrieval Quality is Similar

The ~18-19% area recall@10 across all methods is driven by the WOS dataset's
structure: 336 areas across 45K papers means the average area has ~135 papers.
Random recall@10 would be ~10/45K = 0.0002, so 18% is 900x better than random.
The dataset has strong semantic clustering by area, which both cosine and Poincaré
capture well. The difference between methods is small because both are operating on
the same PCA-reduced semantic embeddings — the distance metric alone (cosine vs
Poincaré-on-a-shell) doesn't change the semantic content.

The real advantage of Poincaré will emerge when:
1. Tier-aware projection places documents at different depths
2. Queries can filter by Busemann depth range (e.g., "find narratives near this topic")
3. Multi-tier search traverses the hierarchy (search near origin → mid → boundary)

## Round 2: Tier-Aware Projection (2026-04-08, evening)

### Approach

Implemented four projection strategies, all at c=5.0, to compare tier-aware
placement against the uniform baseline. Extracted shared math into
`hyperbolic_math.py` and strategies into `projection.py`.

**Strategies tested:**
- `uniform` — L2-normalize, scale 0.9, exp_map (baseline, now correctly applying the normalization)
- `static` — hardcoded per-tier radii (root=0.15, mid=0.50, leaf=0.90) before exp_map
- `einstein` — derive tier center radii via Einstein midpoint calibration, then project
- `einstein_spread` — Einstein-derived centers + intra-tier variance (band_width=0.10)

**Key fix during implementation:** `lorentz_to_poincare()` was missing `sqrt(c)` in the
denominator — the inverse map must undo the `2*sqrt(c)` scaling from the forward map.
Without this fix, all Einstein midpoints clipped at the ball boundary (1/sqrt(c) = 0.447
at c=5.0), making the Einstein strategy degenerate to uniform. This bug also exists in
the Rust-side `poincare_math.rs` and needs to be fixed separately.

### Round 2 Analysis

**1. `einstein_spread` is the clear winner**

The only strategy to beat cosine on ALL retrieval metrics:
- Area recall: 0.216 vs 0.209 (+3.3%)
- Domain recall: 0.583 vs 0.563 (+3.6%)
- H-precision: 0.399 vs 0.386 (+3.4%)
- Busemann separation: 20.4 (3.2x improvement over uniform's 6.4)
- Band overlap: 0.001 (near-perfect tier isolation)

**2. Intra-tier variance is critical**

`static` has perfect band separation (0.000 overlap) but destroys retrieval quality
(area recall 0.160, worst of all strategies). The hardcoded radii place ALL root
vectors at exactly the same radius, ALL mid vectors at another, etc. This collapses
semantic variation within each tier — papers in different areas but the same tier
become equidistant. `einstein_spread`'s `band_width=0.10` preserves within-tier
semantic structure while still enforcing between-tier separation.

The comparison between `einstein` (no spread, area 0.184) and `einstein_spread`
(with spread, area 0.216) directly demonstrates this: adding intra-tier variance
improves area recall by 17%.

**3. Einstein calibration inverts on real data**

The Einstein midpoint radii came out inverted: root=0.426, mid=0.417, leaf=0.199.
The leaf tier (45K vectors) has lower midpoint radius because the many vectors
cancel directionally, pulling the midpoint toward the origin. Root (10 vectors) has
high radius because with so few vectors, they don't cancel as much.

This is not a bug — it reflects that Einstein midpoint measures "directional
consensus," not "tier depth." The monotonic sort corrects the ordering. On real
Pythia data where tiers have structurally different embedding distributions (stories
are centroids of posts, narratives are centroids of stories), the radii may
naturally order correctly.

**4. Why 20% recall improvement was too aggressive a target**

WOS is a shallow 3-level taxonomy where the semantic content is strong and uniform.
The embedding model (pplx-embed-v1) already captures area-level clustering well in
cosine space. Hyperbolic depth adds hierarchy awareness but doesn't change the
underlying semantic content. A 3-4% improvement on flat academic data is a positive
signal — on Pythia's deeper, more heterogeneous hierarchy (posts → stories →
narratives), the depth encoding should matter more.

**5. Latency is a non-issue**

All strategies are 5.4-6.5ms p95 at ef=128, well under 50ms. The projection
strategy choice doesn't affect query-time performance (it only affects index-time
projection).
